## 1️⃣ 포스터 초안 검토 및 개선 방향 논의

- 기존 초안에서 개선할 부분
    - 서비스의 전체적인 기능은 전달되지만 핵심 차별점이 상대적으로 눈에 띄지 않음
    - 일부 영역에서 기능 설명과 기술 설명이 중복됨
    - 기술적 구현 내용을 설명하는 문장이 길어 전체적으로 정보량이 많아 보임
    - 성능 개선 수치와 해당 수치가 의미하는 기술적 성과의 연결이 부족함
    - 구매 Agent가 일반 자동입찰과 어떻게 다른지 보다 직관적으로 전달할 필요가 있음
- 최종 수정 방향
    - 프로젝트를 처음 접하는 관람객도 포스터만 보고 서비스의 목적과 이용 방법을 이해할 수 있도록 구성
    - 기획 배경 → 문제 정의 → 해결 방법 → 차별점 → 사용 흐름 → 핵심 기술 순서로 자연스럽게 읽히도록 정리
    - 핵심 기능과 기술적 기여가 연결되도록 설명 수정
    - 중복되는 설명을 줄이고 실제 서비스 화면과 인포그래픽의 비중 확대
    - 구매 Agent PIKI의 차별점과 주요 성능 개선 결과를 시각적으로 강조

    - 섹션별 배경색, 제목 크기, 강조 요소를 통일하여 전체적인 디자인 일관성 확보

    - Background: 중고 신발의 상태·색상·구성품에 따른 가격 차이
    - Problem: 판매자와 구매자가 기존 거래 과정에서 겪는 문제

    - 아이콘과 화살표의 스타일 및 방향 통일

## 3️⃣ 섹션별 설명 문구 및 핵심 메시지 수정

- Background 영역
    - 중고 신발은 같은 모델이라도 상태·색상·구성품에 따라 가치가 달라진다는 점 강조
    - 단순히 중고거래 시장을 소개하는 것보다 Autique가 중고 신발에 주목한 이유를 설명
    - 실제 가격 차이를 보여주는 사례를 활용하여 문제 상황을 직관적으로 전달
    - 이후 Problem 영역으로 자연스럽게 연결되도록 문구 정리
- Problem 영역
    - 판매자: 상품 정보 입력 및 적정 판매 가격 결정의 어려움
    - 구매자: 가격의 적절성 판단, 반복적인 상품 탐색 및 직접 입찰의 부담
    - 판매자와 구매자의 문제를 구분하여 배치
    - 각 문제가 Solution 영역의 기능과 대응되도록 문구 수정
- Solution 영역
    - 사진 기반 AI 상품 분석을 통한 상품 등록 과정 간소화
    - 중고 거래 데이터 기반 추천 가격 및 가격 산정 근거 제공
    - 실시간 경매를 통해 실제 구매 수요를 최종 거래 가격에 반영
    - AI 추천 가격이 실제 상품 가치를 확정하는 것이 아니라 판매자의 가격 판단을 돕는 참고 기준임을 명확히 함
- WHY AUTIQUE 및 Differentiator 영역
    - 사진만으로 간편하게 상품을 등록할 수 있다는 점 강조
    - 단순 가격 추천이 아닌 산정 근거까지 제공한다는 점 강조
    - 구매 Agent가 상품 탐색부터 자동입찰까지 수행한다는 점 강조
    - 일반 자동입찰과 구매 Agent의 차이를 명확하게 구분
        - 일반 자동입찰: 사용자가 선택한 특정 경매에서 설정한 상한까지 입찰
        - 구매 Agent: 구매 목표를 유지하며 조건에 맞는 경매를 탐색하고 자동입찰 수행
    - 낙찰 실패 이후에도 구매 기한 내 다른 경매를 재탐색하는 구조를 핵심 차별점으로 설명
    - 기존 서비스에서 제공하지 않는 기능이라는 단정적인 표현보다 Autique가 여러 구매 과정을 하나의 목표 기반 흐름으로 연결했다는 점 강조
- 구매 Agent 명칭 및 표현 통일
    - 구매 Agent 명칭은 PIKI(피키)로 통일
    - 포스터, 서비스 UI, 발표 대본에서 동일한 명칭 사용
    - AI Agent, 구매 Agent, Purchase Agent 등의 표현이 혼용되지 않도록 정리
    - 기술적 용어보다 관람객이 이해하기 쉬운 표현 우선 사용

## 4️⃣ User Flow 및 서비스 화면 세부 수정

- 판매자 User Flow
    - 사진 업로드 → AI 상품 분석 → 추천 가격 확인 → 경매 등록
    - 실제 서비스 화면을 활용하여 사용 과정이 순차적으로 보이도록 구성
    - AI 분석 결과를 판매자가 직접 확인하고 수정할 수 있다는 점 반영
    - 추천 가격과 함께 가격 산정 근거를 확인할 수 있는 화면 강조
    - 상품 등록 과정의 세부 입력 항목을 모두 보여주기보다 핵심 사용자 경험 위주로 정리
- 구매자 User Flow
    - 자연어 구매 목표 입력 → 구매 조건 확인 → 경매 탐색 → 자동입찰 → 낙찰
    - PIKI에게 원하는 신발과 예산·구매 기한을 입력하는 실제 화면 활용
    - AI가 해석한 구매 조건을 사용자가 확인할 수 있는 과정 포함
    - 구매 Agent가 탐색과 입찰을 대신 수행하는 흐름을 직관적으로 표현
- 구매 Agent 순환 구조 개선
    - 기존의 일방향 처리 흐름만으로는 낙찰 실패 후 재탐색하는 특징이 잘 드러나지 않음
    - 경매 탐색 → 자동입찰 → 결과 확인 → 재탐색의 순환 구조를 인포그래픽으로 표현
    - 낙찰 성공 시 구매 목표 완료 및 탐색 종료
    - 낙찰 실패 시 구매 기한 내 다른 경매 재탐색
    - 구매 기한 만료 시 탐색 종료
    - 성공과 실패에 따른 분기 및 화살표 방향을 명확하게 구분
- 서비스 화면 정리
    - 실제 구현된 서비스 화면을 기준으로 이미지 선정
    - 피그마 디자인과 실제 서비스의 화면 차이 확인
    - 화면 속 텍스트가 지나치게 작아지지 않도록 이미지 크기 조정
    - 각 화면 하단의 설명 문구를 짧고 일관된 형태로 정리
    - 발표 시 포스터의 User Flow를 따라 실제 서비스 시연으로 자연스럽게 연결할 수 있도록 구성

## 5️⃣ Key Features 영역 및 기술 설명 개선

- 기술 설명 전체 수정 방향
    - 기술 스택이나 라이브러리 이름을 나열하는 방식 지양
    - 기능별로 해결해야 했던 문제, 적용한 처리 방식, 검증 결과가 연결되도록 구성
    - 관람객이 이해할 수 있는 수준의 설명과 기술적 세부 내용 사이의 균형 조정
    - 본문에는 핵심 설계만 포함하고 상세 구현 내용은 발표 및 질의응답에서 보충
- 중고 시세 기반 추천가 산정
    - 중고 거래 데이터를 활용한 모델·색상별 시세 산정 방식 설명
    - 상품 상태 및 박스 유무에 따른 가격 차이를 반영하는 구조 강조
    - 단순 평균 가격을 제공하는 것이 아니라 상품별 특성을 고려하여 추천 가격을 산정한다는 점 전달
    - 중고 시세가 없는 경우 대체 시세를 활용하고 산정 근거가 부족하면 시세 없음으로 처리하는 방식 설명
    - 데이터 규모와 가격 산정 방식을 시각적으로 연결
    - 추천 가격 계산 예시는 실제 데이터 및 계수를 기준으로 제시
- AI 상품 분석 및 처리 속도 개선
    - 실루엣·라벨·상태 분석을 병렬로 수행하는 구조 표현
    - 기존 순차 분석 방식과 개선된 병렬 분석 방식의 차이를 시각화
    - 이미지 크기 및 프롬프트 최적화 내용 포함
    - 평균 Vision 분석 시간 14.9초 → 4.7초를 주요 개선 지표로 강조
    - 분석 결과가 불확실한 경우 임의로 값을 생성하지 않고 사용자 확인을 유도하는 설계 반영
    - 전체 상품 등록 시간이 아닌 Vision 분석 소요 시간이라는 점 명확히 표기
- AI 분석 Worker 분리
    - 상품 분석 중에도 경매 및 입찰 요청을 처리할 수 있도록 별도 Worker로 분리한 구조 설명
    - API 서버 → Redis Streams → AI 분석 Worker 흐름을 간단한 구조도로 표현
    - Worker 중단 시 미완료 작업을 회수하여 재처리하는 방식 설명
    - 작업 소유권 검증을 통해 이전 Worker의 뒤늦은 결과 저장을 방지하는 구조 반영
    - 전체 시스템 아키텍처와 중복되는 내용은 줄이고 핵심적인 분리 목적과 효과 중심으로 정리
- 실시간 경매의 동시 입찰 처리
    - 수동입찰·일반 자동입찰·구매 Agent가 동일한 경매에 참여할 수 있는 구조 설명
    - 동시 입찰로 인해 가격 및 낙찰자 정합성이 깨질 수 있다는 문제 제시
    - 경매별 비관적 락을 통해 입찰 검증과 가격 갱신을 순차적으로 처리하는 방식 표현
    - 정합성 위반 3/20 → 0/20의 개선 결과를 주요 수치로 활용
    - 동시 입찰 전후의 차이를 쉽게 이해할 수 있도록 인포그래픽 구성
    - 부하 테스트의 처리 성공 여부와 최종 거래 결과의 정합성을 구분하여 설명
- 구매 Agent의 판단 및 입찰 검증 구조
    - AI가 자연어 구매 조건을 구조화하고 적합한 경매를 판정하는 역할 설명
    - AI의 판단만으로 입찰을 실행하지 않고 서버에서 거래 조건을 검증하는 구조 강조
    - 입찰 직전 서버에서 계산한 시세와 사용자 예산을 기반으로 입찰 상한 설정
    - 입찰 상한 = min(사용자 예산, 서버 시세 × 설정 배수)
    - AI는 해석·판정, 서버는 검증·제한·실행을 담당하도록 역할 구분
    - 구매 목표 확인 및 낙찰 후 사용자 결제 승인 과정을 통해 사용자 통제권을 유지한다는 점 전달

## 6️⃣ 성능 지표 및 실험 결과 최종 검토

- 중고 시세 데이터 규모
    - 133개 모델 · 34개 브랜드 · 거래 데이터 7,768건을 최종 데이터 규모 지표 후보로 사용
    - 발표 시 약 7,800건으로 설명하는 방식 검토
    - 기존 데이터 집계 결과인 65개 모델·6,173건과 최신 집계 수치가 혼용되지 않도록 정리
    - 상태 계수 산정에 사용한 표본 1,884건의 별도 표기 여부 검토
    - 판매 호가와 실거래가를 구분하여 실제 수집 데이터의 성격에 맞는 용어 사용
- AI 상품 분석 속도
    - 기존 평균 Vision 분석 시간: 14.9초
    - 개선 후 평균 Vision 분석 시간: 4.7초
    - 평균 분석 소요 시간 약 68.5% 감소
    - 실제 매물 14건, 사진 3~6장 기준의 실험 조건 명시
    - 사진 업로드 및 대기열 소요 시간이 제외된 측정값임을 표기
- 실시간 경매 정합성
    - 동일한 통제 조건에서 각 20회 동시입찰 실험 진행
    - 비관적 락 적용 전 정합성 위반 3건
    - 비관적 락 적용 후 정합성 위반 0건
    - 실험 결과를 모든 상황에서 오류가 발생하지 않는다는 의미로 확대 해석하지 않도록 표현 수정
- 경매 부하 테스트
    - 가상 사용자 100명 부하에서 요청 실패 0건
    - 150 VU부터 일부 연결 거부가 발생했다는 점을 고려하여 처리 한계와 정합성 검증 결과 구분
    - 처리 완료된 요청을 기준으로 최종 가격 및 낙찰자 오류가 없었음을 명확하게 표기
    - 부하 테스트의 전체 측정 구간 및 실험 조건 최종 확인
- AI 정확도 평가
    - 기존 평가 결과 96.6%와 신규 매칭 평가 결과 99%의 평가 대상 및 표본 구분
    - 서로 다른 평가 결과를 상품 분석 정확도 또는 Agent 매칭 정확도로 혼용하지 않도록 확인
    - 실제 매물 67건 기준 매칭 정확도 및 잘못 선택한 매물 0건의 집계 기준 재확인
    - 정확도 수치는 최종 평가 자료와 일치하는 값만 반영
- 성능 지표 표기 방식
    - 개선 전 → 개선 후 형태로 주요 성과를 직관적으로 표현
    - 핵심 숫자는 크게 강조하고 측정 조건은 하단에 별도 표기
    - 포스터와 발표 대본에 사용하는 수치 및 용어 통일
    - 실험으로 검증한 범위를 넘어서는 표현은 사용하지 않음

## 7️⃣ 최종 포스터 검토 및 발표 연계 사항 논의

- 최종 디자인 검토
    - 전체적인 정보 배치 및 주요 섹션 구성 확정
    - 각 영역의 제목, 설명 문구, 이미지, 인포그래픽 간 일관성 확인
    - 오탈자 및 영문 대소문자 표기 점검
    - 불필요하게 반복되는 문장과 기술 설명 정리
    - 실제 출력 크기를 고려하여 본문 글자 크기와 이미지 해상도 확인
- 포스터와 발표 대본 연계
    - Background → Problem → Solution → Differentiator → User Flow → Key Features 순서로 발표 진행
    - 포스터에 작성된 내용을 그대로 읽기보다 각 영역을 가리키며 자연스럽게 설명
    - User Flow 설명 이후 관람객 참여형 서비스 시연 진행
    - 시연에서 확인한 기능을 Key Features의 기술 설명과 연결
    - 포스터에 담기 어려운 상세 기술 내용은 질의응답에서 보충
- 서비스 체험 관련 요소
    - 관람객이 직접 Autique에 접속할 수 있도록 서비스 체험 QR 배치
    - QR 코드의 크기 및 실제 인식 가능 여부 확인 필요
    - 시연 영상 및 추가 프로젝트 자료 연결 여부 검토
    - 실제 서비스 화면과 포스터에 사용한 화면의 일치 여부 최종 확인
- 사용자 테스트 결과 반영
    - 사용자 테스트 결과가 확보되면 핵심 정량 지표 및 대표 사용자 의견 반영 검토
    - 포스터 전체 레이아웃을 크게 변경하지 않는 범위에서 결과 추가
    - 아직 측정하지 않은 결과는 임의로 작성하지 않음
    - 포스터 반영이 어려운 상세 결과는 발표 및 질의응답 자료에서 활용
- 최종 확정 사항
    - 포스터의 전체적인 레이아웃 및 콘텐츠 구성은 현재 시안을 기준으로 확정
    - 핵심 디자인 방향과 서비스 전달 메시지 유지
    - 이후에는 전체 구성을 변경하기보다 문구·수치·정렬·출력 관련 세부 수정 위주로 진행
    - 최종 출력 전 팀원 전체 검토 및 남은 수정 사항 반영
