## 2️⃣ 등록 흐름에 남은 차이 해결 방법 논의

- 문제 1: 등급 값이 API마다 다름
    - 분석 결과 DS/A/B/C/UNKNOWN, 가격 계산 DS/S/A/B/C/UNKNOWN, 경매 상세 A/B/C
    - 명세는 `UNKNOWN`이면 사용자가 등급을 직접 고르라고 하지만, 피그마 2/6 화면에는 등급 입력이 없음
- 문제 2: 등록 요청에 저장할 곳이 없는 값
    - 2/6에서 고치는 "상태" 문장(`conditionDescription`), 상세에 보여주는 상품명(`name`/`subName`)
- 문제 3: 등록 요청의 `imageUrls`
    - 분석 조회가 주는 URL은 6시간짜리 서명 URL이고, 실서버에서 이 URL로 등록하면 500이 남
    - 사진 ID 방식에서도 `imageUrls`를 보내야 하는지 명세에 없음
- 문제 4: 디자인에 없는 상태
    - 1/6 사진 칸이 맞지 않을 때(`invalid`) 안내 문구와 '다음' 버튼 동작
    - 분석 결과의 확인 필요 안내(`warnings`)를 보여줄 위치
    - 시세가 없어 추천가가 0원일 때의 4/6 화면
    - 가격 계산은 분석 1건당 1번만 됨. 4/6에서 2/6으로 돌아가 값을 바꾸면 처음(1/6)부터 다시 분석해야 함
    - 등록 취소 API는 "X 버튼으로 나갈 때" 쓰는데, 화면 헤더에는 뒤로가기(<)만 있음
- 논의할 것
    - 등급 값을 어디에 맞출지 (FE 쪽 제안: 분석 결과 기준 DS/A/B/C로 통일하고 UNKNOWN일 때만 선택 UI 노출)
    - `conditionDescription`, `name`/`subName`을 등록 요청에 추가할지, 서버가 만들지
    - 등록 중 나가기를 X 버튼으로 바꿀지
