## 1️⃣ 기존 수상작 분석 및 포스터 개선 방향

- 수상작 분석 (트리오링고, SINGCHRONIZE, Optimus Prime)
    - 프로젝트의 문제 상황과 서비스의 필요성을 구체적으로 제시함
    - 실제 서비스 화면, 분석 결과, 추천 리포트 등을 활용해 핵심 기능을 시각적으로 설명함
    - 기술 설명을 단순 기술 스택 나열이 아닌 입력 → 처리 → 출력 흐름으로 구성함
    - 기능별 핵심 처리 로직과 전체 시스템 아키텍처를 구분하여 설명함
    - 프로젝트를 대표하는 기능과 기술적 기여에 더 많은 공간을 할당함
- Autique 포스터 개선 방향
    - 서비스 기능 소개와 기술적 설계가 자연스럽게 연결되도록 구성
    - AI 상품 등록과 구매 Agent의 실제 사용 화면 활용
    - 각 기능에서 발생하는 문제와 이를 해결하기 위해 설계한 처리 방식을 함께 설명
    - 기술명 자체보다 기술을 적용한 이유와 적용 결과를 중심으로 작성
    - 주요 성능 지표와 처리 흐름을 시각화하여 가독성 개선

## 2️⃣ 유사 서비스 조사 및 차별점 논의

- 유사 서비스 기능 조사 내용
    - 당근: 사진 기반 예상 가격 추천 및 AI 판매 글 작성
    - 네이버 플리마켓: 상품 정보 자동 입력 및 상품 상태·유사 상품 가격 기반 AI 시세 제공
    - eBay: AI 상품 정보 입력, 상태 판별 추천, 자연어 기반 상품 탐색, 저장된 검색 및 자동입찰
    - KREAM: 중고 명품의 진위 및 상품 상태 전문 검수
- 기존 서비스와의 차별점
    - 사진 기반 상품 등록과 AI 가격 추천만으로는 차별성을 강조하기 어려움
    - 자연어 기반 상품 탐색과 자동입찰 역시 기존 서비스에서 개별적으로 제공하는 기능임
    - 하나의 구매 목표를 지속적으로 유지하며 경매 탐색부터 조건·시세 검증, 자동입찰, 실패 후 재탐색까지 연결하는 구매 Agent 구조를 핵심 차별점으로 설정
    - 판매자가 설정한 가격이 아닌 서버에서 산정한 시세를 기준으로 입찰 상한을 제한하는 구조 강조
- 핵심 시나리오
    - 구매자가 원하는 모델·상태·사이즈·예산 등의 조건을 자연어로 입력
    - Agent가 조건에 맞는 경매를 탐색하고 입찰 상한 내에서 자동입찰
    - 낙찰 실패 시 설정한 기한 내에 다른 경매 재탐색
    - 낙찰 성공 시 구매 목표 완료 및 탐색 종료
    - 구매 목표 등록 → 경매 탐색 → 자동입찰 → 실패 시 재탐색 / 낙찰 시 종료

## 3️⃣ 포스터에 포함할 핵심 기술 및 성능 지표 논의

- 실시간 경매의 동시 입찰 처리
    - 수동입찰·자동입찰·구매 Agent가 동일한 경매에 동시에 참여할 때 발생하는 정합성 문제 설명
    - 경매별 비관적 락을 적용하여 최신 가격 조회, 입찰 검증, 가격 갱신을 순차적으로 처리
    - 동시 입찰 실험 각 20회 기준 정합성 위반 3회 → 0회
    - 가상 사용자 100명 부하에서 요청 실패 0건
    - 부하 테스트의 요청 처리 성공 여부와 거래 결과의 정합성을 구분하여 표기
- AI 상품 분석 및 분석 Worker 분리
    - 실루엣(브랜드·모델·색상), 라벨(사이즈), 상태(등급·하자) 분석을 병렬 처리
    - 분석 근거가 부족한 항목은 임의로 생성하지 않고 사용자 확인·수정을 유도
    - API 서버와 AI 분석 Worker를 분리하여 상품 분석 중에도 경매·입찰 요청을 처리할 수 있도록 설계
    - Redis Streams 기반 작업 전달 및 XCLAIM을 통한 미완료 작업 회수·재처리
    - 작업 소유권 검증을 통해 이전 Worker의 뒤늦은 결과 저장 방지
    - Vision 분석 평균 소요 시간 14.9초 → 4.7초
    - 실제 매물 14건, 사진 3~6장 기준이며 업로드 및 대기열 시간은 제외한다는 측정 조건 명시
- 중고 거래 데이터 기반 추천가 산정
    - 당근·후르츠패밀리 거래 데이터를 활용하여 모델·색상별 시세 산정
    - 상태 등급 및 박스 유무에 따른 가격 차이를 실제 데이터 기반으로 반영
    - 중고 시세가 없는 경우 KREAM 새제품가, 브랜드 전체 시세 순으로 대체 산정
    - 대체 시세를 사용한 경우 참고용 가격임을 안내하고, 산정 근거가 없는 경우 "시세 없음"으로 처리
    - 포스터에 사용할 데이터 규모 지표 선정 필요
        - 후보 1: 65개 모델 · 거래 데이터 6,173건 · 상태 계수 표본 1,884건
        - 후보 2: 133개 모델 · 34개 브랜드 · 거래 데이터 7,768건
    - 데이터 규모와 추천가 산정의 근거 중 어떤 부분을 강조할지 논의
    - 판매 호가와 실거래가의 구분 및 데이터 집계 기준 확인 필요
- 구매 Agent의 판단 및 입찰 안전성
    - 자연어 구매 조건을 AI가 구조화하고 경매 매물과의 조건 일치 여부를 판정
    - 모델·상태·사이즈 조건을 기반으로 후보를 선별하고 시세 대비 가격을 기준으로 우선순위 결정
    - 입찰 직전 서버에서 시세를 다시 산정하여 입찰 상한 설정
    - 입찰 상한 = min(사용자 예산, 서버 시세 × 설정 배수)
    - 시세보다 높은 가격에 입찰하는 경우 시세 대비 금액 안내
    - 구매 조건은 사용자 확인 후 등록하고, 낙찰 후 결제는 사용자가 직접 승인
    - AI는 조건을 해석하고 서버는 검증·제한·실행하는 역할 분리 강조
    - 실제 매물 67건 기준 매칭 정확도 99%, 잘못 선택한 매물 0건을 성능 지표 후보로 선정
    - 최종 정확도 산정 기준 및 평가 결과 재확인 필요

## 4️⃣ 포스터 전체 구성 논의

- Section 1. 기획 배경 및 문제 정의
    - 같은 모델이라도 상태·색상·구성품에 따라 가치가 달라지는 중고 신발의 특성 설명
    - 판매자: 상품 정보 입력 및 적정 판매 가격 설정의 부담
    - 구매자: 반복적인 상품 탐색, 가격 비교 및 직접 입찰의 부담
    - 시세 기반 가격 판단 지원과 경매를 통한 실제 구매 수요 반영을 해결 방법으로 제시
- Section 2. AI 상품 등록 및 추천가 산정
    - 사진 업로드 → AI 분석 → 사용자 확인·수정 → 추천가 확인 → 경매 등록
    - 실제 상품 등록 화면과 AI 분석 결과 화면 활용
    - 병렬 분석 방식과 추천가 산정 근거를 시각화
    - 분석 시간 개선 결과 및 시세 데이터 규모 강조
- Section 3. 구매 Agent
    - 자연어 구매 조건 입력 예시와 실제 Agent 사용 화면 활용
    - 조건 해석 → 사용자 확인 → 경매 후보 선택 → 자동입찰 → 결과에 따른 재탐색 또는 종료
    - 입찰 상한 계산 방식 및 사용자 보호 설계 설명
    - 기존 서비스와의 핵심 차별점인 구매 목표 기반 반복 탐색 구조 강조
- Section 4. 핵심 시스템 설계 및 안정성
    - 실시간 경매의 동시 입찰 처리 구조
    - AI 분석 Worker 분리 및 장애 복구 구조
    - 정합성 실험 및 부하 테스트 결과 활용
    - 전체 시스템 아키텍처를 해당 영역에 통합할지 별도 영역으로 구성할지 논의
- Section 5. 사용자 테스트 및 서비스 체험
    - 기존 방식과 Autique의 상품 등록·가격 결정·상품 탐색 과정 비교
    - 사용자 테스트를 통해 측정한 정량적 지표와 정성적 의견 반영
    - 서비스 체험 QR 및 시연 영상 QR 배치
- 디자인 구성 방향
    - 구매 Agent와 AI 상품 등록을 주요 기능 영역으로 배치
    - 기술적 처리 과정은 텍스트보다 흐름도와 인포그래픽을 적극 활용
    - 핵심 성능 지표는 큰 숫자로 강조하고 세부 측정 조건은 하단에 표기
    - 기능 설명, 핵심 로직, 성능 검증 결과가 연결되도록 구성
