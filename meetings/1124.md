## 2️⃣ 평가 항목별 발표 전략 논의

- 독창성 (30%)
    - 기존 중고거래 서비스와 Autique의 기능 및 구매 방식 비교
    - 사진 기반 상품 등록과 AI 가격 추천은 기존 서비스에서도 제공하는 기능이므로 해당 기능만으로 차별성을 강조하기 어려움
    - 구매 Agent PIKI가 구매 목표를 유지하며 경매 탐색·조건 검증·자동입찰·미낙찰 후 재탐색을 수행하는 구조를 핵심 차별점으로 강조
    - 일반 자동입찰과 구매 목표 기반 Agent의 차이를 구체적인 시나리오로 설명
    - 기존 기능의 단순 결합이 아니라 구매자의 반복적인 거래 과정 자체를 자동화했다는 점 전달
- 기술적 난이도 (20%)
    - 단순 LLM API 활용이나 기술 스택 나열보다 구현 과정에서 해결한 기술적 문제 중심으로 설명
    - 상품 이미지 분석의 속도 및 정확도 개선
    - 중고 거래 데이터 기반 추천 가격 산정 및 데이터 부족 상황 처리
    - 수동입찰·자동입찰·구매 Agent가 동시에 참여하는 경매의 정합성 확보
    - AI 분석 Worker 분리 및 장애 발생 시 작업 복구 구조
    - 구매 Agent의 AI 판단과 서버의 거래 검증을 분리한 설계
    - 각 기술을 적용한 이유와 적용하지 않았을 때 발생할 수 있는 문제를 함께 설명
- 완성도 (30%)
    - 상품 등록부터 경매 참여, 낙찰, 결제까지 연결되는 전체 서비스 흐름 강조
    - 실제 동작하는 서비스 화면과 Live 데모 활용
    - AI 분석 시간 개선, Agent 매칭 평가, 동시입찰 정합성 및 부하 테스트 결과 제시
    - 사용자 테스트를 통해 기존 거래 방식 대비 편의성 및 서비스 가치 검증
    - 최초 기획 단계에서 정의한 판매자·구매자의 문제가 실제로 얼마나 해소되었는지 결과와 연결
    - 구현 완료 기능과 검증 범위, 남아 있는 한계를 명확하게 구분
- 발표력 (20%)
    - 프로젝트를 처음 접하는 교수님도 이해할 수 있는 발표 흐름 구성
    - 문제 상황을 먼저 설명하고 해결 방법과 구현 결과를 순차적으로 전달
    - 기능 및 기술 설명이 서로 분리되지 않고 자연스럽게 연결되도록 구성
    - 실제 화면, 구조도, 그래프를 활용하여 구두 설명에 대한 의존도 감소
    - 대본을 그대로 읽는 방식보다 핵심 내용을 이해하고 설명하는 방식으로 연습
    - 예상 질문을 작성하고 팀원 간 모의 질의응답 진행

## 3️⃣ 최종 발표 전체 구성 및 핵심 메시지 논의

- 포스터 발표와 최종 졸업발표의 차이
    - 포스터 발표는 관람객이 서비스를 쉽게 이해하고 직접 체험하는 데 집중
    - 최종 졸업발표는 프로젝트의 필요성, 독창성, 기술적 난이도, 완성도를 제한된 시간 안에 전달해야 함
    - 기존 포스터의 설명 순서를 그대로 사용하기보다 교수님이 제시한 발표 권장 내용을 기준으로 재구성
    - 기능을 소개하는 것에서 나아가 왜 해당 기능과 기술이 필요했고 어떤 결과를 얻었는지 설명
- 전체 발표 흐름
    - 프로젝트 소개
    - 기획 배경 및 문제 정의
    - 기존 서비스 분석 및 차별점
    - Autique의 해결 방법 및 사용자 흐름
    - 핵심 기능별 기술적 문제와 해결 방법
    - 기술 성능 평가 및 사용자 테스트 결과
    - 서비스 데모
    - 결론 및 기대 효과
- 프로젝트 배경에서 강조할 내용
    - 교수님 공지에서 프로젝트 배경을 가장 중요한 부분으로 강조함
    - 왜 필요한지, 왜 중요한지, 왜 해결하기 어려운지에 대한 설명 필요
    - 같은 모델의 중고 신발이라도 상태·색상·구성품에 따라 가치가 달라지는 특성 제시
    - 판매자는 적정 가격을 판단하기 어렵고 구매자는 원하는 상품을 반복적으로 검색하고 비교해야 하는 문제 설명
    - 이러한 문제를 뒷받침할 실제 매물 사례, 유사 서비스 조사 및 사용자 테스트 결과 활용
- 발표의 핵심 메시지
    - Autique는 단순한 중고 신발 경매 플랫폼이 아니라 판매자와 구매자의 거래 과정 전반을 AI로 지원하는 서비스
    - 판매자에게는 상품 등록과 가격 판단을 지원
    - 구매자에게는 원하는 상품의 탐색과 입찰 과정을 자동화
    - AI의 유연한 판단과 서버의 규칙 기반 거래 검증을 결합하여 실제 거래 과정에 적용
- 발표자료 작성 방향
    - 한 슬라이드에는 하나의 핵심 메시지를 중심으로 구성
    - 기능별 설명은 문제 → 해결 방법 → 검증 결과가 연결되도록 작성
    - 슬라이드 제목만 읽어도 전체 발표 흐름을 이해할 수 있도록 구성
    - 기술적 세부 구현 및 추가 실험 결과는 질의응답용 백업 슬라이드로 분리하는 방안 검토

## 4️⃣ 최종 발표자료 슬라이드 초안 구성

- Slide 1. 프로젝트 소개
    - Autique 로고, 서비스명, 팀명 및 팀원 소개
    - AI 기반 중고 스니커즈 경매 플랫폼이라는 서비스 정체성 전달
- Slide 2. Background
    - 같은 모델이라도 상품 상태·색상·구성품에 따라 가격이 달라지는 중고 신발의 특성
    - 실제 중고 매물의 가격 차이 사례 활용
    - 중고 신발의 적정 가치를 판단하기 어려운 이유 설명
- Slide 3. Problem
    - 판매자의 상품 등록 및 가격 결정 부담
    - 구매자의 반복 탐색, 가격 비교 및 직접 입찰 부담
    - 기존 거래 방식에서 발생하는 사용자 문제 구체화
- Slide 4. 기존 서비스 분석 및 차별점
    - 당근·네이버 플리마켓·eBay·KREAM 등 유사 서비스 조사 결과 활용
    - AI 상품 등록, 가격 추천, 상품 탐색, 자동입찰 등 기존 기능 비교
    - 개별 기능을 넘어 구매 목표 기반으로 거래 과정을 연결하는 PIKI의 차별성 강조
- Slide 5. Solution 및 User Flow
    - 판매자: 사진 업로드 → AI 분석 → 추천 가격 확인 → 경매 등록
    - 구매자: 구매 목표 입력 → 조건 확인 → 경매 탐색 → 자동입찰 → 낙찰 또는 재탐색
    - 실제 서비스 화면을 활용하여 전체 사용자 흐름 설명
- Slide 6. System Architecture
    - FE·BE·AI 서버 간 전체 시스템 구조 설명
    - 상품 분석, 가격 추천, 경매 처리 및 구매 Agent의 역할 구분
    - 주요 데이터 흐름과 서버 간 연동 구조 설명
- Slide 7. AI 상품 분석
    - 사진 기반 브랜드·모델명·색상·사이즈·상태 분석
    - 실루엣·라벨·상태 분석의 병렬 처리 구조
    - 이미지 크기 및 프롬프트 최적화
    - 평균 Vision 분석 시간 14.9초 → 4.7초 개선 결과
- Slide 8. 중고 시세 기반 추천가 산정
    - 모델·색상별 중고 시세 데이터 구축
    - 상품 상태 및 박스 유무에 따른 가격 차이 반영
    - 시세 데이터가 부족한 상황에서의 대체 산정 및 시세 없음 처리
    - 실제 상품의 추천 가격과 산정 근거 예시 활용
- Slide 9. 구매 Agent PIKI
    - 자연어 구매 조건 해석 및 구조화
    - 조건에 맞는 경매 탐색 및 후보 선택
    - 자동입찰과 낙찰 실패 후 재탐색 과정 설명
    - 일반 자동입찰과 구매 Agent의 동작 범위 비교
    - Agent 매칭 성능 평가 결과 활용
- Slide 10. 구매 Agent의 판단 및 입찰 검증 구조
    - AI는 구매 조건 해석 및 경매 적합성 판정 담당
    - 서버는 실제 거래 조건 검증 및 입찰 실행 담당
    - 사용자 예산과 서버 시세를 기반으로 입찰 상한 제한
    - AI의 판단 오류가 실제 거래로 이어지지 않도록 설계한 방식 설명
- Slide 11. 실시간 경매의 동시입찰 처리
    - 여러 입찰 방식이 동일한 경매에 참여할 때 발생하는 정합성 문제
    - 경매별 비관적 락을 적용한 순차 처리 구조
    - 동시입찰 정합성 위반 3/20 → 0/20 개선 결과
    - 부하 테스트를 통한 요청 처리 및 거래 결과 검증
- Slide 12. AI 분석 Worker 분리 및 안정성
    - 오래 걸리는 AI 분석 작업과 실시간 경매 요청의 실행 구조 분리
    - Redis Streams 기반 작업 전달 및 별도 Worker 처리
    - 미완료 작업 회수·재처리 및 결과 저장 보호 구조
    - 필요시 전체 시스템 구조도 또는 AI 상품 분석 슬라이드와 통합 검토
- Slide 13. 사용자 테스트 및 서비스 가치 검증
    - 기존 시세 조사 방식과 Autique AI 가격 추천 방식 비교
    - 직접 상품 탐색과 구매 Agent 초기 설정 방식 비교
    - 소요 시간, 조작 횟수, 완료율 및 사용자 선호도 결과 활용
    - 실제 사용자의 주요 의견 및 서비스 개선점 정리

- Slide 14. Demo
    - AI 상품 분석 및 추천 가격 확인
    - PIKI 구매 목표 설정 및 경매 탐색
    - 실시간 자동입찰·낙찰 결과 확인
    - 낙찰 실패 후 재탐색 과정은 별도 결과 화면 또는 영상 활용 검토

## 6️⃣ Live 데모 진행 방식 및 발표 시간 배분 논의

- 데모 진행 기준
    - 교수님 공지에서 Live 데모를 권장하고 있으므로 실제 서비스 시연을 우선 고려
    - Live 데모 진행이 어려운 경우 녹화 영상 활용 가능
    - 시간이 오래 걸리는 기능은 초기 실행 과정을 보여주고 최종 결과를 별도로 준비하는 방식 검토
    - 강의실의 Windows 환경에서 화면 연결, 영상 재생 및 서비스 접속 여부 사전 확인 필요
- 포스터 발표 시연과의 차이
    - 포스터 발표에서는 관람객이 직접 상품을 등록하고 경매에 참여하는 방식으로 진행
    - 최종 졸업발표에서는 준비 및 데모 시간을 포함해 전체 발표가 10분으로 제한됨
    - 관람객 참여형 전체 경매 시연보다 핵심 기능을 빠르게 보여주는 방식으로 재구성 필요
    - 실제 동작 여부와 서비스의 차별점이 명확하게 전달되는 장면 위주로 선정
- Live 데모 후보
    - 실제 신발 사진 업로드 및 AI 상품 분석
    - AI 추천 가격과 산정 근거 확인
    - PIKI에게 자연어 구매 조건 입력
    - AI가 해석한 조건 확인 및 구매 목표 등록
    - PIKI의 경매 탐색 및 자동입찰 결과 확인
    - 실시간 입찰 현황 및 낙찰 결과 확인
- 데모 시간 단축 방안
    - 상품 등록용 사진과 테스트 계정 사전 준비
    - 로그인 및 서비스 접속을 발표 시작 전에 완료
    - 구매 조건에 맞는 테스트용 경매 사전 등록
    - 전체 경매 진행시간을 기다리는 대신 사전에 준비한 경매의 입찰 및 낙찰 결과 활용 검토
    - Agent의 탐색 및 AI 호출 대기시간이 발표 흐름을 지연시키지 않도록 구성
    - 미낙찰 후 재탐색처럼 시간이 필요한 과정은 녹화 영상 또는 실제 결과 화면 활용
- 발표 시간 배분 초안
    - 발표 준비 및 화면 전환: 30초
    - 프로젝트 소개·배경·문제 정의: 1분 30초
    - 기존 서비스 분석 및 핵심 차별점: 1분
    - 해결 방법 및 핵심 기술 설명: 3분
    - 기술 평가 및 사용자 테스트 결과: 1분 30초
    - 서비스 데모: 2분
    - 결론 및 마무리: 30초
    - 총 10분
    - 실제 리허설 결과에 따라 슬라이드 수와 구간별 시간 재조정
- 데모 실패 대응 방안
    - 네트워크 연결 및 외부 AI API 호출 실패에 대비한 녹화 영상 준비
    - 분석·경매 탐색·자동입찰·낙찰 결과의 실제 화면 사전 확보
    - Live 데모 실패 시 즉시 준비된 영상으로 전환할 수 있도록 구성
    - 발표자료와 데모 영상은 인터넷 연결 없이도 재생할 수 있도록 준비
