## 1️⃣ 동률 입찰 및 차순위 구매 제안 오류 공유

- 문제 상황
    - 동일 금액으로 입찰했을 때 실제 낙찰자와 차순위 순위표의 결과가 일치하지 않는 문제 발생
    - 낙찰자가 구매를 포기하거나 결제 기한을 넘기면 본인에게 다시 차순위 구매 제안이 전달됨
    - 해당 구매 제안을 수락하면 기존 낙찰 주문과 중복되어 500 오류 발생
- 발생 원인
    - 입찰 엔진과 차순위 순위표의 동률 처리 기준이 서로 다름
        - 입찰 엔진: 동일 금액에서 자동입찰 우선
        - 차순위 순위표: `Bid` 저장 순서 기준
    - 실제 낙찰자가 아닌 순위 번호를 기준으로 차순위 후보를 선정하면서 대상 불일치 발생
    - 기존 주문 및 구매 제안 이력이 후보 선정 과정에 충분히 반영되지 않음

## 2️⃣ 차순위 후보 선정 및 구매 제안 로직 변경

- 동률 입찰 정렬 기준 변경
    - 동일 금액에서는 `AUTO` Bid를 `MANUAL` Bid보다 먼저 정렬하도록 수정
    - 입찰 엔진과 차순위 순위표의 자동입찰 우선 처리 기준을 일치시킴
- 차순위 후보 선정 방식 변경
    - 순위 번호 대신 실제 낙찰자·처리된 사용자·기존 구매 제안 이력을 기준으로 후보 선정
    - 실제 낙찰자를 제외한 상위 2명으로 차순위 후보 범위 고정
    - 이미 구매 제안을 받은 사용자에게 다시 제안하지 않도록 수정
    - 실제 낙찰자에게 차순위 구매 제안이 전달되는 문제 방지
- 구매 제안 처리 경로 통일
    - 최초 낙찰자의 구매 포기
    - 최초 낙찰자의 결제 기한 만료
    - 차순위 구매 제안 거절
    - 차순위 구매 제안 기한 만료
    - 모든 경로에서 동일한 차순위 후보 선정 방식 적용
- 차순위 구매자의 수락 이후 처리
    - 차순위 구매자가 제안을 수락한 후 구매를 포기하는 경우에도 다음 후보에게 구매 제안이 전달되도록 수정
    - 기존 제안 이력을 확인하여 동일 사용자에게 중복 제안하지 않도록 처리
- 기존 정합성 보장 로직 유지
    - 기존 DB 잠금 순서 유지
    - 잠금 획득 후 주문 및 제안 상태를 재검증하는 로직 유지
    - DB 수준의 중복 방지 제약 유지

## 3️⃣ 테스트 및 검증 결과 공유

- 차순위 후보 선정 통합 테스트
    - `BackupCandidateSelectionMySqlIT`: 9건 통과
    - 수정 전 코드에서 동률 입찰 관련 테스트 4건 실패 확인
    - 최종 정렬 변경만 되돌렸을 때 테스트 2건 실패 확인
    - 동률 처리 및 차순위 후보 선정 로직에 대한 회귀 검증 완료
- 차순위 후보 선정 단위 테스트
    - `BackupCandidateSelectorTest`: 8건 통과
    - 관련 서비스 및 Repository 테스트 통과
    - 기존 MySQL 원자성·동시성 테스트 통과
- 구매 제안 처리 동시성 테스트
    - `BackupOfferResolutionRaceMySqlIT`: 3개 테스트를 각각 10회 반복하여 총 30회 통과
    - 검증한 동시 요청 시나리오
        - 구매 제안 거절 vs 제안 기한 만료
        - 기한이 지난 구매 제안 수락 vs 제안 기한 만료
        - 차순위 주문 포기 vs 결제 기한 만료
    - 동시에 요청이 발생하는 상황에서도 관련 동시성 테스트 통과 확인
- 검증 범위 및 한계
    - 관련 단위·서비스·Repository·MySQL 통합 테스트 통과
    - 전체 테스트 스위트는 실행하지 않음
    - 이미 잘못 생성된 운영 데이터에 대한 수정 및 검증은 진행하지 않음

## 4️⃣ API 영향 범위 및 연동 사항 논의

- API 변경 사항
    - 기존 API 경로·요청·응답 구조·상태 코드 변경 없음
    - 동률 입찰 사례에서 경매 결과 조회의 `rank`, `backupEligible` 값이 변경됨
    - 실제 낙찰자 및 변경된 차순위 선정 결과를 기준으로 응답
- FE 확인 사항
    - 경매 결과 화면에서 실제 낙찰자와 차순위 구매 가능 여부가 올바르게 표시되는지 확인
    - 동률 입찰 시 `rank`, `backupEligible` 값을 기준으로 화면이 정상적으로 표시되는지 확인
    - 구매 제안 수락·거절·만료 및 주문 포기 이후 화면 상태 갱신 확인
- DB 및 배포 관련 사항
    - DB 스키마 변경 및 마이그레이션 불필요
    - 기존 잠금 및 중복 방지 제약 유지
    - 이미 잘못 생성된 주문·구매 제안 데이터는 이번 PR에서 수정하지 않음
    - 기존 운영 데이터의 오류 발생 여부 및 별도 정리 필요성 확인
