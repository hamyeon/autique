## 1️⃣ 포스터 발표 구성 및 대본 작성

- 전체 발표 흐름
    - 서비스 소개 → 기획 배경 → 문제 정의 → 해결 방법 → 차별점 → User Flow → 서비스 시연 → 핵심 기술 설명 → 마무리
    - 포스터의 각 영역을 가리키면서 설명하는 방식으로 진행
    - 일방적인 설명보다 관람객과의 상호작용 및 직접 체험을 중심으로 구성
    - 실제 서비스 동작을 먼저 보여준 뒤, 해당 기능을 구현하기 위해 적용한 기술을 설명하는 방식으로 구성
- 서비스 소개 및 기획 배경 (Background)
    - 중고 거래 경험과 거래 과정에서 느꼈던 불편함에 대해 관람객에게 질문
    - 같은 모델의 신발이라도 상태·색상·구성품에 따라 가격이 달라지는 특성 설명
    - 관람객이 기존 중고 거래에서 경험한 문제를 Autique의 기획 배경과 연결
- 문제 정의 (Problem)
    - 판매자: 적정 판매 가격을 결정하기 어렵고 직접 상품 정보를 입력해야 하는 부담
    - 구매자: 제시된 가격의 적절성을 판단하기 어렵고 원하는 상품을 반복적으로 탐색해야 하는 부담
- 해결 방법 (Solution)
    - 사진 기반 AI 상품 분석으로 상품 정보 입력 과정 간소화
    - 중고 거래 데이터를 활용한 추천 가격 및 산정 근거 제공
    - 추천 가격만으로 개별 상품의 실제 가치를 확정하기 어렵다는 점을 설명
    - 실시간 경매를 통해 실제 구매 수요가 최종 거래 가격에 반영되도록 설계
- 핵심 차별점 (Differentiator)
    - 구매 Agent의 이름을 PIKI(피키)로 소개
    - 자연어로 입력한 구매 조건을 바탕으로 경매 탐색 및 자동입찰 수행
    - 낙찰에 실패하더라도 구매 기한 내 다른 경매를 다시 탐색하고 입찰을 이어가는 구조 강조
    - 단순 상품 추천이나 특정 경매의 자동입찰을 넘어 구매 목표를 지속적으로 수행한다는 점을 핵심 차별점으로 설명

## 2️⃣ User Flow 설명 방식 논의

- 판매자 사용 흐름
    - 사진 업로드 → AI 상품 분석 → 분석 결과 확인·수정 → 추천 가격 확인 → 경매 등록
    - AI가 브랜드·모델명·색상·상태 등의 상품 정보를 자동으로 분석
    - 판매자가 분석 결과를 직접 확인하고 필요한 항목을 수정할 수 있음을 설명
    - 추천 가격과 가격 산정 근거를 참고하여 경매 시작 가격 결정
    - 상품 정보 입력 및 직접 시세 조사에 대한 부담 감소 강조
- 구매자 사용 흐름
    - 자연어 구매 목표 입력 → 구매 조건 확인·수정 → 경매 탐색 → 자동입찰 → 낙찰 또는 재탐색
    - 구매 목표 입력 예시: "이번 주 안에 아식스 노바블라스트를 30만 원 이하로 사고 싶어"
    - 구매 Agent가 자연어 요청을 분석하여 상품 조건·예산·구매 기한을 구조화
    - 구매자가 AI가 해석한 조건을 확인한 뒤 탐색 시작
    - 구매 Agent가 조건에 맞는 경매를 탐색하고 설정된 입찰 상한 내에서 자동입찰
    - 낙찰 성공 시 결과 안내 및 결제 단계로 연결
    - 낙찰 실패 시 구매 기한 내 다른 경매 재탐색
- User Flow 설명 이후 실제 서비스 시연으로 연결
    - 설명한 기능을 관람객이 직접 체험할 수 있도록 진행
    - PIKI를 통한 구매, 일반 자동입찰, 수동입찰의 차이를 동일한 경매에서 비교

## 3️⃣ 관람객 참여형 서비스 시연 시나리오 논의

- 시연 진행 방식
    - 관람객이 직접 상품 등록 및 경매에 참여하는 방식으로 진행
    - 관람객 본인의 신발을 등록하거나 팀에서 준비한 신발 활용
    - 아이폰 화면을 맥북에 미러링하여 다른 관람객도 서비스 동작을 확인할 수 있도록 구성
    - 참여 인원에 따라 팀원이 부족한 역할을 대신 수행
- 참여자 역할 구성
    - 참여자 1: 판매자 역할, 사진 촬영 및 AI 상품 분석·경매 등록
    - 참여자 2: 구매 Agent PIKI를 이용한 경매 참여
    - 참여자 3, 5: 일반 자동입찰을 이용한 경매 참여
    - 참여자 4, 6: 수동입찰을 이용한 경매 참여
    - 참여자가 3명인 경우 팀원이 수동입찰 역할 담당
- 시연 1: AI 상품 분석 및 경매 등록 (약 2분)
    - 신발의 측면·정면·밑창 사진 촬영 및 업로드
    - AI 상품 분석 결과 확인
    - 실제 상품과 분석 결과가 다른 경우 사용자 직접 수정
    - 구성품 등 추가 정보 입력
    - 추천 가격 및 가격 산정 근거 확인
    - 추천 가격을 참고하여 경매 시작 가격 설정
    - 빠른 시연을 위해 경매 진행시간을 2분으로 설정
- 시연 2: 구매 Agent PIKI 설정 및 경매 탐색
    - 참여자가 원하는 신발과 예산·구매 기한을 자연어로 입력
    - 방금 등록한 상품을 탐색할 수 있도록 구매 조건 입력 안내
    - 경매 시작 가격을 고려하여 예산 설정
    - AI가 해석한 구매 조건을 사용자가 직접 확인하고 수정할 수 있음을 설명
    - 탐색 시작 후 PIKI가 경매를 찾아 자동입찰하는 과정 확인
- 시연 3: 일반 자동입찰 설정
    - 상품 상세 페이지에서 자동입찰 예약
    - 최대 입찰 가능 금액 설정
    - PIKI와 일반 자동입찰의 상한 금액을 다르게 설정하여 입찰 과정 비교
    - 일반 자동입찰은 사용자가 직접 선택한 특정 경매에서 동작한다는 점 설명
- 시연 4: 수동입찰 및 실시간 경매 진행 (경매 진행시간 약 2분)
    - 참여자가 실시간 경매 현황을 확인하면서 직접 입찰
    - PIKI·일반 자동입찰·수동입찰이 동일한 경매에서 동작하는 모습 확인
    - 수동입찰은 사용자가 직접 경매 상황을 확인하고 입찰해야 한다는 점 설명
    - 실시간 현재가 및 입찰 현황 변화를 미러링 화면으로 공유
    - 입찰 방식별 사용자 개입 정도와 편의성 차이 강조
- 시연 5: 경매 종료 및 결과 확인 (약 30초)
    - 경매 종료 후 실제 낙찰자 및 최종 낙찰 가격 확인
    - 낙찰자의 결과 확인 및 결제 화면 진입
    - 낙찰자가 구매를 포기하거나 결제 기한을 넘긴 경우 차순위 구매자에게 구매 기회가 이어지는 정책 설명
    - 실제 결제를 진행할지 여부는 별도 결정 필요
- 시연 진행 시 확인할 사항
    - 구매 Agent의 스캔 주기와 AI 호출 시간을 고려하여 경매 시작 전 구매 조건 설정 시간 확보
    - 일반 자동입찰 예약 및 PIKI 탐색이 충분히 이루어질 수 있도록 진행 순서 조정
    - 마감 직전 입찰로 인한 경매 연장 및 서버의 종료 확정 시간 고려
    - 상품 분석 실패, 추천가 산정 불가, Agent 매칭 실패 등에 대비한 대체 시연 준비
    - 전체 시연 소요 시간은 실제 리허설을 통해 확인

## 4️⃣ 핵심 기술 및 성능 지표 설명 방법 논의

- 기술 설명 구성 방향
    - 시연에서 관람객이 직접 확인한 기능을 다시 언급하며 기술 설명으로 연결
    - 기술 스택을 나열하기보다 해당 기능에서 해결해야 했던 문제와 구현 방법을 중심으로 설명
    - 가격 추천의 근거, AI 분석 속도, 경매 안정성, 구매 Agent의 판단 구조를 중심으로 구성
- 중고 시세 기반 추천가 산정
    - 약 7,800건의 중고 거래 데이터를 활용한 추천가 산정 방식 설명
    - 동일 모델이라도 상품 상태에 따라 가격이 달라지는 점을 반영
    - 단순 평균 시세가 아닌 개별 상품의 상태를 고려한 추천 가격 제공
    - 추천 가격과 산정 근거를 함께 제공하여 사용자의 가격 판단 지원
    - 최종 발표 전 데이터 집계 수치 및 실거래가·판매 호가 관련 용어 확인 필요
- AI 상품 분석 및 성능 최적화
    - 이미지 크기 및 프롬프트 최적화
    - 기존 순차 분석 방식을 병렬 분석 방식으로 변경
    - Vision 평균 분석 시간 14.9초 → 4.7초로 단축
    - 분석 작업을 별도 Worker로 분리하여 경매·입찰 등 다른 서버 요청과 독립적으로 처리
    - 분석 속도 개선과 함께 정확도 평가 결과 설명
    - 대본에 포함된 정확도 96.6%가 어떤 기능의 평가 결과인지 확인하고 평가 대상에 맞게 표현 수정 필요
    - Vision 분석 시간과 전체 상품 등록 소요 시간을 구분하여 설명
- 실시간 경매의 안정성
    - 여러 구매자가 동시에 입찰하는 상황에서 최종 가격 및 낙찰자 정합성 확보 필요
    - 경매별 잠금을 통해 입찰 검증 및 가격 갱신을 순차적으로 처리하는 구조 설명
    - 동시입찰 실험 및 부하 테스트를 통해 거래 결과의 정합성 검증
    - 필요시 정합성 위반 3/20 → 0/20 및 가상 사용자 100명 부하에서 요청 실패 0건의 수치 활용
    - 부하 테스트의 요청 처리 성공 여부와 거래 결과의 정확성을 구분하여 설명
- 구매 Agent의 판단 및 입찰 검증 구조
    - AI는 자연어 구매 조건을 해석하고 적합한 경매를 탐색하는 역할 수행
    - 실제 입찰 가능 여부와 금액 제한 등 거래 규칙은 서버에서 검증
    - 사용자 예산과 서버에서 계산한 시세를 기준으로 입찰 상한 제한
    - AI가 해석한 조건을 사용자가 확인하고, 낙찰 후 결제는 사용자가 승인
    - AI의 유연한 판단과 서버의 규칙 기반 거래 처리를 분리한 설계 강조

## 5️⃣ 발표 진행 및 마무리 방식 논의

- 발표 진행 방향
    - 포스터에 작성된 문장을 그대로 읽기보다 관람객에게 설명하는 자연스러운 방식으로 진행
    - 포스터의 Background·Problem·Solution·Differentiator·User Flow·Key Features 영역을 순서대로 활용
    - 관람객의 반응 및 참여 인원에 따라 설명과 시연 방식 조정
    - 서비스 이용 방법과 기술 설명에서 동일한 내용이 과도하게 반복되지 않도록 대본 조정
- 핵심 전달 메시지
    - 판매자의 상품 등록 및 가격 판단 부담 감소
    - 구매자의 상품 탐색 및 반복 입찰 부담 감소
    - 단순 상품 추천을 넘어 구매 목표를 유지하며 실제 거래 과정까지 지원하는 AI Agent
    - AI의 판단과 서버의 거래 검증을 분리하여 서비스 안정성 확보
- 발표 마무리
    - 판매자와 구매자 양측의 거래 과정을 지원하는 서비스라는 점 재강조
    - AI가 정보를 제공하는 데 그치지 않고 실제 거래 과정까지 지원한다는 메시지 전달
    - 발표 종료 후 관람객 및 심사위원 질의응답 진행
