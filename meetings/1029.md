## 1️⃣ 졸업발표 준비 방향 논의

- 발표의 핵심 목표
    - Autique가 어떤 문제를 해결하기 위해 만들어진 서비스인지 명확하게 전달
    - 단순히 구현한 기능을 나열하기보다 서비스의 필요성과 기술적 차별점을 함께 설명
    - 판매자와 구매자 양측에서 Autique를 사용할 이유가 드러나도록 구성
    - 실제 서비스 화면 및 시연을 통해 프로젝트의 완성도를 보여주는 방향으로 진행
- 핵심적으로 강조할 기능
    - AI 사진 분석을 통한 상품 정보 자동 입력
    - 중고 거래 데이터 기반 추천 가격 및 산정 근거 제공
    - 실시간 경매 및 자동입찰
    - 자연어 기반 구매 Agent의 경매 탐색 및 입찰 자동화
- 차별점 전달 방향
    - 사진 기반 상품 등록과 가격 추천만으로는 기존 중고거래 서비스와의 차별성이 부족할 수 있음
    - 구매 Agent가 단순히 상품을 추천하는 것이 아니라 구매 목표를 바탕으로 실제 입찰까지 수행한다는 점 강조
    - 낙찰 실패 시 구매 기한 내 다른 경매를 재탐색하는 구조를 핵심 시나리오로 활용
    - 유사 서비스 기능 조사를 통해 Autique만의 차별점을 구체화할 예정

## 2️⃣ 구매 AI Agent 네이밍 및 브랜딩 논의

- 네이밍 목적
    - 구매 AI Agent를 단순 기능명이 아닌 독립적인 서비스 내 캐릭터로 표현
    - 사용자가 Agent를 친근하게 느끼고 쉽게 부를 수 있도록 이름 선정
    - 포스터, 서비스 UI, 발표 및 시연에서 일관된 명칭 사용
- 네이밍 선정 기준
    - 짧고 발음하기 쉬운 이름
    - 귀엽고 친근하면서도 미니멀한 느낌
    - 상품을 잘 찾아주고 선택해 주는 Agent의 역할이 직관적으로 드러나는 이름
    - 서비스 내 진행 상태 및 안내 문구에 자연스럽게 활용할 수 있는 이름
    - 특정 동물이나 캐릭터에 반드시 한정하지 않음
- 네이밍 후보
    - Piki(피키): 부르기 쉽고 귀여우면서도 미니멀한 AI Agent 이름. Pick을 연상시키는 명칭
    - Pickat: Pick + Cat. 고양이처럼 원하는 상품을 찾아 콕 집는 이미지
    - Pika(피카): 짧고 친근한 캐릭터형 AI 이름
    - Findy(파인디): Find에서 파생된 이름으로 원하는 상품을 찾아주는 역할 강조
    - Nabbit: Nab + Rabbit. 원하는 상품을 빠르게 찾아 잡는 이미지
    - 퍼랭이: 캐릭터의 외형 및 색상과 연결할 수 있는 친근한 이름
- 네이밍 선정
    - 기능 전달력, 발음의 편의성, 캐릭터 확장 가능성 등을 고려하여 후보 비교
    - 최종 명칭은 Piki(피키)로 선정하는 방향
    - 영문 표기 및 대소문자 표기 방식 통일 필요
- 서비스 내 활용 문구 논의
    - "피키가 조건에 맞는 경매를 찾고 있어요."
    - "피키가 대신 입찰하고 있어요."
    - "피키가 새로운 경매를 탐색하고 있어요."
    - "피키가 원하는 신발을 낙찰받았어요!"
- 추가 논의 사항
    - 구매 Agent 전용 캐릭터 또는 아이콘 제작 여부
    - Agent의 탐색·입찰·재탐색·낙찰 상태별 캐릭터 표현
    - Autique의 기존 브랜드 디자인과 Agent 디자인의 통일성 확보

## 3️⃣ 포스터 양식 및 디자인 방향 논의

- 기존 졸업 프로젝트 포스터 레퍼런스 조사
    - ModalArc, 200OK, NexStep, Flippers, MIND 등의 포스터 구성 및 디자인 참고
    - 기존 수상작의 정보 배치, 핵심 기능 설명 방식, 기술적 성과 표현 방식 추가 조사
    - 프로젝트를 처음 접하는 관람객도 서비스를 빠르게 이해할 수 있는 구성 검토
- 포스터 디자인 방향
    - 서비스의 정체성이 드러나면서도 시각적으로 눈에 잘 들어오는 디자인
    - 많은 내용을 담더라도 영역별 구분과 정보의 중요도가 명확하게 드러나도록 구성
    - 긴 줄글보다는 실제 서비스 화면, 아이콘, 흐름도, 인포그래픽 활용
    - 핵심 성능 개선 결과와 데이터 규모는 숫자를 중심으로 강조
    - 기존 Autique의 서비스 UI 및 브랜드 컬러와 통일성 유지
    - 색상, 타이포그래피, 섹션별 배치 등은 여러 디자인 시안을 비교하여 결정
- 포스터에 포함할 주요 영역 초안
    - Introduction: 서비스 및 팀 소개
    - Background: 중고 신발 거래의 특성과 기획 배경
    - Problem: 판매자 및 구매자가 겪는 문제
    - Solution: AI 상품 분석, 가격 추천, 실시간 경매
    - Differentiator: 기존 서비스와 Autique의 차별점
    - User Flow: 판매자 및 구매자의 서비스 이용 흐름
    - Key Features: 주요 기능의 기술적 구현 방식
    - System Architecture: 전체 시스템 구조
    - Evaluation: 기술 성능 검증 및 사용자 테스트 결과
- 포스터 콘텐츠 구성 방향
    - 서비스 소개 영역과 기술 설명 영역을 구분
    - 판매자의 상품 등록 과정과 구매자의 Agent 이용 과정을 하나의 거래 흐름으로 연결
    - 구매 Agent의 탐색·입찰·실패 후 재탐색 구조를 시각적으로 강조
    - 핵심 기능별로 구현 방법과 성능 개선 결과를 함께 배치
    - 전체 시스템 구조도의 위치 및 크기는 포스터 초안 제작 후 결정
- 포스터 제작 방식
    - Figma를 활용하여 전체 레이아웃 및 디자인 시안 제작
    - 각 기능 담당자가 포스터에 들어갈 기술 설명 및 성능 지표 정리
    - 팀원 간 피드백을 통해 정보량과 가독성을 조정
    - 최종 포스터 제작 전 출력 규격 및 해상도 확인

## 4️⃣ 졸업발표 진행 방식 및 시연 아이디어 논의

- 발표 진행 방향
    - 포스터에 작성된 내용을 그대로 읽는 방식보다 관람객에게 직접 설명하는 방식으로 진행
    - 관람객에게 중고 거래 경험 및 불편했던 점을 질문하여 서비스 소개로 연결
    - 기술 설명에 앞서 Autique가 해결하려는 문제와 실제 사용 방법을 전달
    - 설명만 진행하는 것보다 관람객이 직접 서비스를 체험할 수 있는 참여형 발표 검토
- 전체 발표 흐름 초안
    - 서비스 소개 및 기획 배경
    - 판매자·구매자의 문제 상황 설명
    - Autique의 해결 방법 및 핵심 차별점 소개
    - 실제 서비스 이용 흐름 설명
    - 관람객 참여형 서비스 시연
    - 핵심 기술 및 성능 검증 결과 설명
    - 마무리 및 질의응답
- 서비스 시연 아이디어
    - 시연용 신발 2개 정도를 준비하여 관람객이 직접 상품 등록
    - 관람객 본인의 신발을 촬영하고 AI 상품 분석 및 추천 가격 확인
    - 구매 Agent에게 자연어로 원하는 신발과 구매 조건을 입력하는 체험
    - Agent가 조건에 맞는 경매를 탐색하고 자동입찰하는 과정 확인
    - 여러 관람객이 동일한 경매에 참여하는 실시간 경매 시연
    - 구매 Agent·일반 자동입찰·수동입찰의 차이를 직접 체험하는 방식 검토
    - 낙찰 실패 시 다른 경매를 재탐색하는 Agent의 동작 시연
- 관람객 참여 방식
    - 포스터에 서비스 접속용 QR 코드를 배치하여 개인 기기로 체험할 수 있도록 구성
    - 진행자가 준비한 기기를 활용한 시연과 관람객 개인 기기를 활용한 체험을 병행하는 방향 검토
    - 관람객 수에 따라 참여 역할을 유동적으로 배정
- 시연 관련 고려 사항
    - 관람객의 신발을 직접 분석할 경우 상품 식별 및 시세 산정에 실패할 가능성 존재
    - 안정적인 시연을 위해 분석 결과가 확인된 신발 및 테스트 경매를 사전에 준비할 필요가 있음
    - 제한된 발표 시간 안에 경매 등록부터 낙찰까지 진행할 수 있도록 경매 시간 정책 조정 검토
    - 구매 Agent의 탐색 주기 및 AI 분석 소요 시간을 고려한 시연 순서 설계 필요
    - 네트워크 및 서비스 오류 발생에 대비하여 예비 시연 영상이나 결과 화면 준비
    - 세부 발표 대본 및 시연 역할 분담은 포스터 구성 확정 후 진행

## 5️⃣ 사용자 테스트 진행 방향 논의

- 사용자 테스트 필요성
    - 기술적 성능 개선 수치뿐만 아니라 실제 사용자에게 제공하는 서비스 가치 검증 필요
    - AI 가격 추천이 판매자의 가격 결정 부담을 줄이는지 확인
    - 구매 Agent가 구매자의 상품 탐색 및 반복 입찰 부담을 줄이는지 확인
    - 사용자들이 AI에게 구매 조건 해석 및 자동입찰을 위임할 의향이 있는지 확인
- 테스트 진행 방향
    - 프로젝트 개발에 참여하지 않은 외부 사용자를 대상으로 진행
    - 참가자가 직접 Autique의 주요 기능을 체험하도록 구성
    - 기존 중고거래 방식과 Autique 이용 방식의 비교 가능성 검토
    - 가격 추천과 구매 Agent를 중심으로 사용자 테스트 과제 구성
    - 시간, 조작 횟수, 성공 여부 등 정량적 지표와 사용자 의견을 함께 수집
- 주요 측정 지표 후보
    - 직접 시세 조사와 AI 가격 추천의 소요 시간
    - 직접 상품 탐색과 구매 Agent 초기 설정의 소요 시간
    - AI가 해석한 구매 조건의 일치 여부
    - 상품 탐색 및 구매 조건 설정 과정의 사용자 조작 횟수
    - AI 추천 가격 및 산정 근거의 도움 정도
    - 구매 Agent의 편의성 및 자동입찰 위임 의향
    - 실제 서비스 이용 의향 및 개선 요청 사항
- 테스트 결과 활용 방향
    - 포스터의 Evaluation 영역에 사용자 테스트 결과 반영
    - 기존 방식과 Autique의 차이를 정량적 지표로 시각화
    - 사용자 자유응답을 통해 서비스의 장점 및 개선점 도출
    - 실제 측정 결과를 바탕으로 발표에서 강조할 기능 및 메시지 선정
- 세부 테스트 계획
    - 참가자 수, 테스트 소요 시간, 과제별 제한 시간 등은 후속 회의에서 확정
    - 진행자 기록지 및 최종 설문 문항 별도 제작
    - 본 테스트 전 파일럿 테스트를 통해 진행 방식 및 측정 기준 검토

## 6️⃣ 졸업발표 준비 단계 및 후속 회의 계획

- 1단계: 전체 기획 방향 설정
    - 졸업발표에서 강조할 핵심 기능 및 서비스 차별점 선정
    - 구매 Agent 네이밍 및 브랜딩 방향 결정
    - 포스터 레퍼런스 및 디자인 방향 논의
    - 관람객 참여형 시연 및 사용자 테스트 진행 방향 설정
- 2단계: 포스터 콘텐츠 및 디자인 기획
    - 기존 졸업 프로젝트 수상작 분석
    - 유사 서비스 기능 조사 및 Autique의 차별점 구체화
    - 포스터 섹션별 핵심 문구 작성
    - 각 기능의 기술적 구현 방식 및 성능 지표 정리
    - Figma 포스터 초안 제작 및 팀원 피드백 진행
- 3단계: 서비스 완성도 점검 및 시연 환경 준비
    - 상품 등록·경매·자동입찰·구매 Agent의 FE·BE·AI 연동 상태 확인
    - 전체 사용자 흐름에서 발생하는 오류 및 미구현 기능 점검
    - 졸업발표 시연에 필요한 경매 시간 정책 및 Agent 실행 주기 검토
    - 시연용 계정·상품·경매 데이터 준비
    - 서비스 체험 QR 및 예비 시연 영상 준비
- 4단계: 사용자 테스트 설계 및 진행
    - 테스트 대상 및 핵심 검증 지표 확정
